SSL Pinning 기능 자체가 클라이언트에 파일 또는 하드코딩으로 작업되는 기능
	- 관리 포인트를 웹으로 옮기면 Pinning으로서의 의미가 없어짐

SSL Pinning을 구현할수 있는 방법 2가지
	- 인증서 파일을 활용한 체크
	- 공개키를 활용한 체크

	차이점
		- 공개키를 활용하면 앱 업데이트를 하지 않아도 되지만 키 순환 정책에 위배됨. 키는 주기적인 변환이 필요함.
		- 인증서 파일을 기준으로 작업하면 인증서 만료일에 따라 앱 업데이트를 진행하면서 유지보수에 신경을 써주어야함.

Android에서 필요한 부분
	1. pem string 내려 받을 수 있게 http로 받을 수 있어야됨.
	2. inswave에서 InAppUpdate에서 호출하고 있는 Api 네트워크 모듈에서 인증서 바이패스 시켜주는 코드 지원 필요함.
	3. 앱 실행 플로우 변경 필요 pem string을 먼저 내려받고 이후 플로우 동작 할수 있도록

	** WebView 피닝은 수동으로 구현 할 수가 없을듯? sslerror가 뜨면 정책상 유저한테 물어봐야함.
	
IOS에서 필요한 부분
	1. 웹에서 cer파일 바이너리 내려받아서 UserDefault에 저장가능한지 확인해보고 저장가능하면 저장해서 해당 데이터로 불러와가지고 인증서 피닝이 가능한지 확인.
	  ** 체크 해보니 pem string의 헤더와 개행을 지우고 -> 바이너리로 디코딩 한뒤에 SecCertificate가 생성되는거 확인함. 샘을 있음.
