=================== 회의전 IT 참고사항
 - 최초 설치시 접근권한 안내 이후 가이드화면이 뜨는게 있는데 TO-BE에서는 빠져있어서 확인 필요합니다.
 - 보이는 ARS 사용여부에 따라 AOS의 인트로에서 동의 해야되는 접근권한에 대한 판단이 가능해집니다.
 - 통신 전문 정책 필요
 	* 재시도에 대한 정책 AS-IS는 없습니다.
 	* 통신전문 실패시 AS-IS는 하단 네트워크 오류 팝업만 나타납니다.
 	* 통신전문 실패 에러코드나, 메세지 처리 TO-BE에서는 필요할것으로 생각됩니다.
 - 앱 버전의 통신의 경우 최앞단의 API SSL무시한 통신 고려 필요 (15페이지에 내용 있습니다.)
 	* 예) 앱 버전 체크전문만 Unsafe하게 SSL체크 하지 않는 OkHttpClient 별도 사용
 - 앱업데이트에서 파킹팝업 기능이 들어간것으로 보이는데 13페이지 논의필요합니다. (13~15페이지)
 	* 13페이지 하단에도 적혀있지만 종료 또는 웹 진입을 막는 등의 방식으로 되어 있습니다.
 	* 점검형태의 공지시에서는 공지팝업으로 처리하지 않고 별도의 웹페이지를 진입해서 대기상태로 만들어버리는 형태(개인 의견)
 		** 그외 공지성은 공지팝업 유지

==============================================================================================
AS-IS 구동 과정
	개발버전
		서버 선택 > 접근권한 안내(최초) > 최초 인트로(가이드 팝업)
								 > 최초 아닐시 메인 첫화면 로드(첫화면 로드중에는 로고뷰 최상단에 잠깐) > 회원가입 및 로그인 처리
		서버선택 이후에 선택적으로 디버그 메뉴 열릴 수 있도록 진행 (빌드 단계)
		(TO-BE에서 디버그 메뉴 열릴수 있는 별도 버튼을 만든다고 들었으나 SPA 흐름에 방해되지 않게 하는게 중요.)
	운영버전
		개발버전에서 서버선택, 디버그 메뉴 제외
==============================================================================================
앱 구동 순서 (회의 문서와 비교하면서 다른점 위주로 정리)
1. 앱 시작
	AOS
		구동시 앱 보호 설정으로 실행되는 솔루션은 DroidX, FakeFinder 
		푸시 알림 채널 생성
		FCM등록된 푸시토큰 앱에 저장
	IOS
		구동시 LxShield기능 활용해서 탈옥, 디버거 탐지 체크
		Apns에서 받은 토큰값 FCM솔루션에 등록 이후 솔루션 통해서 가져와서 사용
	공통 
		푸시로 앱 열렸을때 웹이 푸시로 들어온것을 가져가는 형태 (AS-IS 코드 잔류하나 사용하지 않음.)
			* 해당 방식이 적절할지에 대해서는 작업단계에서 확인이 필요. (개인적인 의견)
	다음 화면
		서버선택이나 접근권한 팝업 동일.
2. 서버 선택
 	TOBO 동일하나 다음화면으로 가는것만 다름.

	다음화면
		최초 접근권한 팝업
		권한이 되어 있다면 isDebugMenu플래그에 따른 빌드버전에 맞게 디버그 메뉴 웹이 보이거나 메인화면이 보임.

3. 접근권한 안내
	TOBE와 동일하나 최초 설치했을때 표시되는 가이드 화면이 하나 더 있습니다

4. 인트로 (보안 점검)
	보안점검 동일
	인트로 화면이 덮고있는동안 동일.
	- 아래 공통 전문 TO-BE에서도 사용한다면 필요합니다.
5. 인트로 (앱 버전 확인)
	AS-IS에서 계획만 되고 작업되지 않은 공지 팝업이 함께 녹아 있는것으로 보입니다.
6. 메인 웹 로드
	AS-IS에서는 로그인 처리시 간편인증 (PIN, 패턴, 지문), 공동인증서 화면은 모두 앱입니다.
	 * 다만 호출시작부는 웹이 브릿지 호출하면서 네이티브 화면이 나타납니다.

초기에 공통 전문
	NFilter 공개키
	AES 암호화 키
	공동인증서 발급자 필터
		AOS는 웹스퀘어 엔진 로드 후 인트로 로드하면서 API 콜
		IOS는 인트로에서 버전체크 할때 같이 호출
		** 핵심은 공통 전문 3개는 앱이 실사용 되기전에 메모리에 올라가 있어야 하는 데이터들
공통 참고사항
	FxShield는 빌드된 바이너리를 관리 페이지에서 보안을 적용해서 다시 재패키징 하는 형태
	LxShield는 개발툴에 붙어 있어서 운영 빌드시 적용

통신 오류 시 흐름 결정
	* AS-IS는 별도의 전문 재시도 없이 통신 오류시 네트워크 오류
	 ** 버전체크에서 SSL인증서 에러 발생시에는 error.html(새로운 버전 설치 버튼이 있는 화면)로 이동하고있습니다.
	* 에러 코드와 에러 메세지를 명확히 하는 팝업이 필요합니다.
